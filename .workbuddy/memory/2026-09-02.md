## 改用 SSH 推送至 GitHub（完成）

- remote 本就是 SSH：`git@github.com:style1122/bom-drawing-system.git`（fetch/push 均 SSH），无 git http 代理（此前 HTTPS 失败系硬编码代理端口过期所致）。
- SSH 连通性：`ssh -T git@github.com` 返回 `Hi style1122! You've successfully authenticated` → 通道可用。用户提供的公钥指纹 `SHA256:GGbkBkQl98YtBq7LTqUO7LWWCB8lrNzNzNt5HXq9ATA` 对应私钥位于 `~/.ssh/`，由 SSH 客户端直接读取（无需 ssh-agent，agent 未运行也不影响）。
- `git ls-remote` 确认服务器已存在 `a9937fe`（main tip）与 `47be235`（master）—— 早期含 181MB 构建产物的提交早已推上服务器。
- 推送为轻量快进：`git push origin main` → `a9937fe..9be70f0  main -> main`，仅上传极小增量（新源码/部署脚本），**无需重传历史大对象**。
- 本地 ref store 因早前 `.git` 损坏残留故障：`git fetch`/`git update-ref` 报成功却不写出 `refs/remotes/origin/*`（packed-refs 仅表头、`refs/remotes/` 目录为空）。
  修复：手动写松散引用 `mkdir -p .git/refs/remotes/origin && printf '<sha>\n' > .git/refs/remotes/origin/main`（master 同理 47be235…）。
  修复后 `git status` 显示 `up to date with 'origin/main'`，工作树干净。
- 结论：Spring Boot + MyBatis-Plus 改造已提交（9be70f0）并推送至 GitHub，部署文档 DEPLOY.md 与 deploy/ 脚本一并上线。
