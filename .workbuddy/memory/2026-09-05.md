## ERP 订阅同步"每5分钟重复拉到相同4条"排查与修复
- 现象：用户反馈 `ErpSubscriptionService` 定时轮询（@Scheduled fixedDelay 默认 300000ms=5分钟）每次都打「新增/修改 4 条，删除 0 条，失败 0 条，共 1 页」，但 ERP 侧当天零物料异动 → 明显是增量游标未前进，4 条被反复重拉。
- 根因：游标水位取自 `sscrquery` **响应根级** `lastoperatetime`/`pkvalues`（`page.getLastoperatetime()`/`page.getPkvalues()`）。该根级字段为空或回显请求时间 → 第 259 行 `if (timestamp != null && !timestamp.isEmpty())` 不成立 → **时间戳游标从未落库**；每次轮询都用首轮水位（initTimestamp `2018-01-01 00:00:00`）查 ERP，拉回所有改动时间晚于 2018 的物料（恰为这 4 个）→ 无限重复。（明细级 `detail.lastoperatetime` 才是真实水位，代码本就解析了它。）
- 修复（`ErpSubscriptionService.pullChangesInternal`）：游标水位改从**本页明细**计算「最后处理的一笔」= 最后修改时间最大、时间相同取主键最大（字典序，前提格式 yyyy-MM-dd HH:mm:ss 一致）；不再依赖根级字段。已编辑未提交。
- 构建约束：本环境 Maven 不可用，需构建机 `mvn clean package -DskipTests` 重新打包并重启服务方可生效。
- 上线后需重置卡住的游标，否则首轮仍会按 2018 水位全量重拉一次：
  - 核验：`SELECT * FROM erp_sync_cursor WHERE cursor_key LIKE 'material.MA01.%';`（若 `material.MA01.timestamp` 一直是 `2018-01-01 00:00:00` 即坐实根因）
  - 重置：`UPDATE erp_sync_cursor SET cursor_value='<当前时间 yyyy-MM-dd HH:mm:ss>' WHERE cursor_key='material.MA01.timestamp';`（行不存在则 INSERT）。重置到"现在"后下一轮只拉真正新增的异动，应变为 0 条直至 ERP 真有变更。
