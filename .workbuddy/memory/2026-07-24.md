### 4. 修复Excel导出500错误

原因：`catch(Exception)` 无法捕获 `NoClassDefFoundError` 等 `Error` 类型异常，异常传播到 `GlobalExceptionHandler` 返回通用错误消息。

修复：
- `RequisitionController.java` — 导出方法的 `catch(Exception e)` 改为 `catch(Throwable e)`；`handleError` 新增 JSON 转义防止格式错误
- `RequisitionService.exportExcel()` — 所有字段调用前增加 null 检查（`requisitionDate`、`requisitionNo`、`requester` 等），避免 NPE

## 修复 commons-io 版本冲突导致 Excel 导出 NoSuchMethodError

**问题**：POI 5.2.5 需要 commons-io 2.12+，但 `commons-fileupload 1.5` 传递依赖 commons-io 2.7，Maven 依赖仲裁旧版获胜。

**修复**：
- `pom.xml`（根）— dependencyManagement 新增 `commons-io:2.16.1`
- `bom-service/pom.xml` — 新增 `commons-io` 直接依赖

## 导出图纸无文件时的错误处理优化

**问题**：导出图纸时如果物料暂无图纸文件，后端返回 500 错误 JSON，前端 `window.location.href` 无法捕获，直接显示 JSON 文本。

**修复**：
- `RequisitionController.java` — `exportDrawings` 和 `exportExcel` 方法新增 `catch(BusinessException e)` 分支，业务异常返回 code:200 的 JSON 而非 500
- `RequisitionDetail.vue` — `handleExportDrawings` 和 `handleExportExcel` 从 `window.location.href` 改为 `fetch()` 调用；检查响应 Content-Type，JSON 则 `ElMessage.error()` 弹红字提示，blob 则触发文件下载
- 清理不再使用的 `buildExportExcelUrl`/`buildExportDrawingsUrl` 导入

**验证**：后端 `mvn clean compile` + 前端 `vite build` 均通过
